# Scm2Cpp: 型推論を備えた Scheme から読める C++ への翻訳器

著者: 新妻弘崇 (ORCID 0000-0001-8746-1595)
所属: 大阪公立大学工業高等専門学校
日付: 2026 年 8 月 26 日

---

## Summary (英語版 323 語)

[S1] Scm2Cpp は Scheme の部分集合を、人が読んで編集できる C++ へ翻訳する。
Stalin、Gambit-C、Chicken、Bigloo といった従来の Scheme コンパイラは C を
可搬アセンブラとして扱い、継続渡し・トランポリン・ガベージコレクション・
タグ付けされた、読まれることを意図していないコードを吐く。Scm2Cpp は
Scheme の値に実行時表現を一切与えない。Scheme の整数は C++ の `int` に、
ベクタは `boost::array<double,1025>` に、`(car x)` は `car(x)` になる。型は
一様なボックス表現ではなくプログラム全体の型推論から来て、推論が決められ
なかったものは対象言語のテンプレート仮引数になる。

[S2] 第二の層は書き換えによってプログラムを導出する。素朴な Scheme の
カーネルから出発して、繰り返される移動窓和を前置和の差に縮め、ループ不変
な部分式を前計算表へ持ち上げ、一括再計算を漸進更新へ変える。候補の選択は
コストモデルが行う。導出されたプログラムは元の素朴なプログラムに縛られる
— 同じ数値を印字しなければならず、それは Racket 上でも、翻訳した C++ を
通しても検査される — ので、速くて誤った書き換えは、速くて正しい書き換えを
受理するのと同じ工程で捕まる。

[S3] 第三の層は、任意で、翻訳器の外に置かれ、言語モデルを著作のループに
入れる。モデルは書き換え規則、あるいは保持する価値のある量を提案し、
機械的な関門が生き残るかどうかを決める — 書き換えたプログラムは元と同じ
ものを印字しなければならず、記憶化の提案はさらに、問題サイズを振ったとき
に実行時間の増え方が緩やかにならなければならない。モデルは決して信用され
ず、翻訳の最中に問い合わせられることもない。翻訳は決定的なままであり、
一回の対話が残すのは規則ファイルか書き換えられたカーネル、すなわち人が
読んで保管できる成果物である。

[S4] 翻訳器は Racket で書かれている。Scheme のプログラムと任意の型注釈
ファイルを読み、ヘッダとソースを書く。標準および Boost のコンテナの上に
Lisp の操作を与える、小さなヘッダのみのランタイムを伴う。

## Statement of need (英語版 230 語)

[N1] 読める出力は美意識の問題ではない。翻訳のあとも最適化を続けられる、
ということである。旧版で報告したベンチマークでは、FFT の生成 C++ は Stalin
の出す C と同程度の速度で走り、OpenMP 指示文を*手で*加えるとそれより速く
なった — 出力が読めなければ不可能な一手である。

[N2] 現版はその議論を日常の作業に変える。以前は参照メンバを持つクロージャ
構造にコンパイルされていた末尾再帰の名前付き `let` が、いまは普通の `for`
ループになる。指示文が注釈すべきループが出力に実在するということである。
コマンドラインの設定はそこに OpenMP、OpenMP のターゲットオフロード、
OpenACC の指示文を出し、あるいは認識したループ形を Thrust のアルゴリズムに
書き換える。

[N3] 読みやすさの主張は意図的に範囲を限る。直接翻訳については成り立つ。
生成される C++ は Scheme の構造と名前を写している。導出パスのほうは機械
生成の中間名を吐き、その生の出力は見たとおりのものである。想定する手順は
それを中間結果として扱い、導出されたアルゴリズムを普通の Scheme として
書き直すことで、`examples/kernel-only/` にはそのように書かれたカーネルが
置いてある。

[N4] 想定利用者は、Scheme で数値アルゴリズムの試作をし、黒箱の実行ファイル
ではなく、検査し、調整し、並列化できる C++ を必要とする研究者である。本
ソフトウェアは著者自身の画像処理の仕事で用いられており、遅延ストリームの
対応はそのために加えられた。

## State of the field (英語版 289 語)

[F1] Scm2Cpp にもっとも近いのは Aubrey Jaffer の Schlep `scm2c` であり、
これも Scheme の部分集合を読める C へ翻訳し、型を注釈ファイルから取る。
Scm2Cpp はそのファイル形式を受け継いでいる。違いは、型を宣言させるのでは
なく推論すること、そして決まらなかったものに C++ のテンプレートを使うこと
である。プログラム全体の型推論を行うコンパイラのなかでは Stalin が精神的に
もっとも近いが、あちらは型情報を内部で消費し、機械のための C を吐く。

[F2] 導出層の系譜は別である。等式飽和 (egg)、SPIRAL や FFTW のような変換
生成器、Halide のアルゴリズムとスケジュールの分離、自己調整計算 (Adapton)。
本層はそのいずれよりも狭く、狙いも違う — 移動窓と前置和という一族の書き
換えだけを対象とし、証明や飽和の議論の代わりに出力比較のオラクルを保証と
し、スケジュールでもバイナリでもなく読める Scheme を成果物とする。lasso に
ついて導出される covariance-update 座標降下は glmnet の古典的なアルゴリズム
であって、寄与はアルゴリズムそのものではなく、素朴なプログラムからの機械的
な導出のほうである。

[F3] 提案ツールはさらに二つの流れと交わる。Ruler は有界な項空間の上の等式
飽和によって書き換え規則を推論し、構成によって健全である。提案ツールは
その保証を手放して、列挙できるどの空間の外にもある規則に手を伸ばし、
安全性を実行関門で買い戻す。もう一方では、言語モデルはコンパイラ最適化に
直接適用されてきた — パス列を予測させたり、最適化されたコードを吐かせて
測ったりする。ここでの立場が違うのはモデルの居場所である。モデルが出すのは
候補であって答えではなく、翻訳器の中では決して走らない。だから決定的な
パイプラインは、モデルが何を知っていようといまいと影響を受けない。

## Functionality (英語版 582 語)

[U1] 起動例:

```
$ racket scm2cpp-file.scm -t scm2c.typ sample.scm
$ g++ -std=c++17 -include boost/operators.hpp -include boost/optional.hpp sample.cpp
```

[U2] オプションで型推論 (既定は Hindley-Milner、旧来の関係型実装は環境変数
で選ぶ) と並列バックエンド (`-P omp`、`-P gpu`、`-P acc`、`-P thrust`) を
選ぶ。

[U3] オプションは型推論 (`--inference hm` または `relational`)、並列
バックエンド、そして最適化を全て切った素の翻訳 `-N` を選ぶ。

既定の推論はアルゴリズム W である。遅延ストリームは名前による再帰型で
扱う。`(cons a (delay b))` の型は自分自身を含み、構造的な扱いは出現検査に
拒まれるからである。

関係型推論は miniKanren で書いた Hindley-Milner の型付け関係で、その核の
出現検査は自己参照的な束縛を拒否せず `(==> x t)` と命名する — recursive
miniKanren [niitsuma:2018] の変更であり、単一化を等再帰的にして、同じ
無限型の二つの巻き方が出会えるようにしてある。前向きに走らせれば部分集合を
型付けし、後ろ向きに走らせれば与えた型の項を列挙する — 提案ツールが関門に
欲しい方向である。そしてアルゴリズム W が手渡されるしかない再帰型を導出
する: 整数ストリームはプログラムだけから `mu T. pair num (promise T)` として
戻り、変換規則が導出された型を emitter が既に描画する名前付き
`scm2cpp-stream` に着地させる。被覆されない再帰 — データとしての循環
リスト — は有限サイズの C++ 値を持たないので拒否する。関係が確定させるのは
形だけで、幅はどちらの経路でも広がりパスが実現する — `square` が呼び出し側
が double と言うまでテンプレートのままでいられるのはそのためである。
`--inference relational` の下でスイートは全体が通り、元の関係型実装は
時間予算を超えたときの後退先として残る。

[U4] 導出パスは端から端まで通した実例で動かしてある。系列の後方移動平均を
特徴量とする素朴な最小二乗カーネルが covariance-update 形へ書き換えられる。
そこでは Gram 行列が系列の前置和から O(np) 時間で組み上がり、設計行列は
作られず、罰則の格子はその Gram 行列の上の座標降下で解かれる。導出された
カーネル — lasso と elastic net、ridge、L1 ロジスティック回帰、group lasso、
Yule-Walker 自己回帰、ローリング統計 — は C++ に翻訳され、PyPI に
`scm2cpp-lasso` と `scm2cpp-tfs` として公開されている。それぞれ生成された
C++ を同梱する。したがって導入には
コンパイラが要るが Racket は要らない。CUDA のカーネルは罰則 1 つにスレッド
1 本で格子を解く。計時と、それを測ったハードウェアと、再現するスクリプトは
リポジトリの README にある。

[U5] 3 つの著作ツールは言語モデルに「どこを見るか」を尋ね、そのうえでモデル
の言い分を鵜呑みにすることを拒む。`rule-propose.rkt` は最適化器の形式で
書き換え規則を求め、規則自身の自己テストを走らせ、失敗した試みは証拠として
モデルに差し戻す。`memo-propose.rkt` はどの量を保持するか — 記憶化表、
前置和、Gram 行列 — を尋ね、答えを 2 つの関門にかける。この種の提案は完全に
正しくて、しかも少しも速くないことがありうるからである。書き換えた
プログラムは同じ数値を出さねばならず、かつサイズ引数を振ったときの実行時間の
増え方が緩やかにならねばならない。`repeat-scan.rkt` は自由形式の問いの
代わりに厳密な材料を与える。プログラムが 2 回以上計算する副作用のない部分式
を列挙し、機械的でない部分 — どの重複が表にする価値があるか — だけをモデル
に残す。関門が存在する理由は、でっちあげの構文ではなく、もっともらしい算術
のほうである。lasso の covariance-update 形を尋ねられたローカルモデルは、
それを正しく導出したうえで、前計算が実際には最大窓しか要らないところを系列
の長さに比例して増えると数え違えた。印字された数値はすべて正しく、それを
見抜けるのは計時の関門だけである。モデルには標準入力のプロンプトに答える
シェルコマンドを通して届くので、ローカルでも遠隔でも等しく使え、しかもここ
の他のものを作ったり走らせたりするのにモデルは要らない。

[U6] 44 項目の回帰スイートは、単体試験を 11 本 — 書き換えパス群と、型付け
関係の両方向 — 走らせ、31 本の
プログラムを翻訳してコンパイルし実行し、同じプログラムを Racket で走らせた
出力と突き合わせ — Scheme が仕様なので、ずれていく期待出力ファイルは存在
しない — 最後に Python パッケージと CUDA カーネルを構築する。これは新しく
クローンした状態から継続的インテグレーションで走る。
